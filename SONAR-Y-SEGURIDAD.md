# Hallazgos de Sonar y revisión de seguridad

Los cambios de este paquete corrigen los hallazgos de seguridad, fiabilidad y mantenibilidad incluidos en las capturas y exportaciones compartidas el 2 de octubre de 2026. Una nueva ejecución de SonarCloud sobre el commit desplegado determinará qué avisos quedan abiertos; un *security hotspot* puede seguir requiriendo una revisión manual aunque el código sea seguro.

## CSRF: decisión por perfil

En el perfil `aws`, Auth, Inventory, Orden y Shipping son APIs stateless. La autenticación del backend requiere un Access Token de Cognito en `Authorization: Bearer`, validado por JWKS; los cuatro perfiles no aceptan sesiones de navegador para estas API. El BFF de Next.js mantiene las cookies HttpOnly y comprueba `Origin` en sus mutaciones antes de añadir `Authorization` a la petición saliente. Auth publica sólo GET/OPTIONS y conserva el CSRF predeterminado de Spring. Inventory, Orden y Shipping tienen mutaciones Bearer: sólo se excluyen de CSRF las rutas `/api/inventory`, `/api/inventory/**`, `/api/orders`, `/api/orders/**`, `/api/shipping` y `/api/shipping/**` según el servicio; CSRF permanece habilitado para las demás rutas. No se habilita el inicio de sesión mediante formulario, HTTP Basic, OAuth en navegador ni logout de Spring en el perfil AWS.

En el perfil local OAuth de Auth, Orden y Shipping sí existe `JSESSIONID`: se deja activo el CSRF predeterminado de Spring para los métodos que modifican estado. Los clientes locales que envían POST, PUT, PATCH o DELETE necesitan el token CSRF; no se debe desactivar la protección para hacer funcionar una petición de prueba. El perfil local de Inventory es una API Bearer sin sesión y usa la misma excepción restringida a `/api/inventory` y `/api/inventory/**`.

El control del BFF depende también de mantener `FLASHSTOCK_SITE_URL` en el origen HTTPS exacto y la clave `FLASHSTOCK_SESSION_KEY` privada y estable entre despliegues. Ni la contraseña ni su hash se incluyen en un JWT; Cognito verifica las credenciales, emite el Access Token y administra sus contraseñas. El Refresh Token se conserva en otra cookie cifrada, HttpOnly y Secure.

## Análisis nuevo de SonarCloud

El 2 de octubre, el análisis de `main` informó tres fallos: fiabilidad B por `ShippingService` (línea 628), seguridad D por cinco excepciones CSRF y cobertura de código nuevo 42,9 % (mínimo 80 %; 503 líneas que requieren pruebas). El cálculo de porcentaje y la clasificación de *código nuevo* son del servidor SonarCloud: **la cobertura total local de JaCoCo no permite afirmar que el Quality Gate ya pasó**. Tras publicar el commit, consulta el análisis de ese mismo SHA en [SonarCloud](https://sonarcloud.io/dashboard?id=aronoan_flashstock-microservices&branch=main). La expresión de Shipping se corrigió utilizando el valor original y se añadieron pruebas reales de flujos de negocio. Si la cobertura nueva sigue bajo 80 %, abre la métrica Coverage > New Code > Uncovered Lines del nuevo análisis para ubicar las líneas concretas antes de ampliar pruebas.

Sonar inspecciona `ignoringRequestMatchers` aunque el backend sólo autentique con Bearer. Para cada uno de los cuatro avisos que persistan, revisa **la configuración efectiva del perfil**, comprueba que un POST sin Bearer sea rechazado, que no haya autenticación por cookies y que el BFF exija el origen correcto. Documenta la evidencia en el propio issue. Un comentario sugerido es: «API de recurso stateless con JWT Cognito exclusivamente en Authorization; sin formLogin/httpBasic/oauth2Login ni sesión de Spring, con rutas de excepción acotadas; la cookie HttpOnly termina en el BFF que valida Origin. Revisado contra CSRF». Si esa evidencia es cierta y puedes justificar el riesgo, marca el issue **Accepted** en SonarCloud; los issues aceptados se muestran pero se excluyen de las puntuaciones y del Quality Gate. No lo marques automáticamente como False positive. Si algún servicio pasa a autenticar con cookies, elimina antes la excepción CSRF y adapta el cliente. El envío SMTP de boletas sigue deshabilitado por configuración y no dispone de una ruta pública; la plantilla HTML ahora escapa entradas no confiables, pero el destinatario deberá derivarse del propietario verificado antes de habilitar un envío.
